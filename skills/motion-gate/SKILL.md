# motion-gate — 该不该动

## R — 原文（Reading）

> 一页别贪多：每页保留一两个重点动效就够了，全是动效的页面会显得廉价且卡顿。
>
> — 附录C 第1条

> 建议一页最多用一两个，多了会喧宾夺主。
>
> — 第十二章章首

原书的判断只到「数量」这一层：一两个重点动效，其余克制。它给了上限，没给准入标准——所以读者知道"不要多"，但不知道"哪一两个才配"。

这个 skill 补的就是准入标准：**在数上限之前，先问该不该有。**

---

## I — 方法论骨架（Interpretation）

动效不是免费的装饰，它有成本：用户每次看到都要花认知资源去解析"这是什么意思"。**解析得越快，说明这个动效越该存在；解析不掉，它就是噪声。**

于是有三道闸门，必须依次通过。第一道过不了，后面不用问。

### 第一道：频率闸门（决定「要不要」）

同一个动效，用户一天看 100 次和一生看 1 次，正确的答案完全相反。

| 频率 | 判定 | 理由 |
|---|---|---|
| 每天 100 次以上（快捷键、命令面板、列表键盘导航） | **不做动画** | 第 100 次看到时，300ms 就是 30 秒的纯浪费。高频操作的极致是"感觉不到有中间过程" |
| 每天数十次（悬停、列表项切换、Tab 切换） | **极轻或不做** | 只允许 100–140ms 的透明度或极小位移；宁可没有 |
| 偶发（弹窗、抽屉、Toast、提交反馈） | **常规动画** | 此时用户正在等，动画填补了等待，也确认了"操作生效" |
| 罕见 / 首次（引导、支付成功、里程碑） | **可以给惊喜** | 惊喜预算只在这里花。把这份预算用在每天都见的东西上，是最常见的浪费 |

**这条闸门是硬判据，不是权衡。** 键盘触发的操作不做动画不是偏好问题——Raycast 这类每天开几百次的工具，没有开合动画，那是正确的工程决定。

### 第二道：目的闸门（决定「配不配」）

过了频率闸门，再要求用一句话命名目的。只能是下面六种之一：

| 目的 | 含义 | 允许的频率档 |
|---|---|---|
| **反馈** | 确认系统听到了操作 | 偶发、数十次（极轻） |
| **空间连续性** | 说明元素从哪来、到哪去 | 偶发 |
| **状态变化** | 让状态的改变可被察觉 | 偶发、数十次（极轻） |
| **防止突变** | 内容直接替换会闪，用过渡接住 | 偶发 |
| **解释** | 演示某件事怎么运作（营销页、引导） | 罕见、首次 |
| **愉悦** | 纯情绪价值 | **仅限罕见 / 首次** |

**命名不出来，就不要做。** "看着更高级""更有科技感""别人都有"都不是目的，是想要的理由，不是该有的理由。

### 第三道：位置闸门（决定「动哪个」）

目的成立后，还要选对动的对象。同一个人物有两个选择，选错会让成本翻倍：

- **动结果，不动过程。** 数字更新时动数字，不要动整个卡片；换内容时动内容，不要动容器。
- **动进入，不动常驻。** 元素出现时可以有入场，常驻期间不该持续运动（呼吸、漂浮、缓慢旋转都算常驻运动，一页最多一处）。
- **动被操作的，不动周围。** 用户点的是按钮，反馈就该在按钮上；让整页跟着抖是把自己当成主角。

## A1 — 应用的例子（Past Application）

### 案例 1：命令面板要不要弹出动画

**请求**：「给命令面板加个弹出的缩放动画，像 Linear 那样。」

**过闸**：
1. 频率——命令面板属于每天上百次的操作 → 判定不做。
2. 目的——即使命名为"状态变化"，也过不了第一道闸。

**结论**：不加。理由是高频操作的中间过程必须尽可能短。**允许的例外**：面板出现的瞬间要有极短的透明度过渡（≤80ms）避免视觉硬切，但这属于"防止突变"，不是"弹出"。

### 案例 2：页面显得廉价，想加动效

**请求**：「这个落地页看着很廉价，加些高级动效能不能救？」

**过闸**：
1. 频率——落地页是一次性浏览，允许常规动画。
2. 目的——用户说不出目的，只说"显得廉价" → 目的不成立。

**结论**：不能救。廉价感的来源通常是排版、留白、层级、字重、配色——动效是放大器，不是来源。**用动效去补排版留下的窟窿，产出的正是本书自己反对的"廉价感"。** 此时应该拒绝推荐更强的特效，并指出去做视觉层的事。

### 案例 3：列表删除后的补位

**请求**：「删除一行后下面的行要平滑上移，怎么加？」

**过闸**：
1. 频率——删除是偶发操作，通过。
2. 目的——防止突变（内容突然跳上去会让人失去位置感），通过。
3. 位置——动的是"其余行"，不是被删的那行。

**结论**：加。这是动效最正当的用途之一：它不是装饰，是**空间连续性的维持**。转 `interaction-brief` 写规格，配方见 `reference/recipes.md` 第 14 条。

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个 skill

1. 想给某个地方加动效，但不确定值不值。
2. 觉得页面"闷"，第一反应是加动画。
3. 别人（设计师、AI、竞品）做了某个动效，想照着加。
4. 要为一个高频操作加动画，隐约觉得不对。
5. 要在需求评审里判断"这个动效该不该排进这一期"。
6. 已经加了一堆动效，想知道该砍哪些、留哪些。

### 语言信号

- "这里要不要加个动画"
- "加个动效会不会更好一点"
- "页面有点闷，想加点动的东西"
- "能不能给 XX 也加个动效"
- "这样是不是更高级"
- "这个动效有必要吗"

### 与相邻 skill 的区分

- **vs `interaction-brief`**：方向相反。gate 判"要不要有"，brief 写"有了之后怎么写"。**判断线：决定做没做。** 还没决定 → gate；已决定要加 → brief。
- **vs `motion-audit`**：audit 审的是已有方案的质量，gate 审的是要不要存在。**判断线：东西在不在。** 不存在 → gate；已存在 → audit。
- **vs `motion-term-lookup`**：lookup 回答"叫什么"，gate 回答"该不该"。用户说出效果名之后才轮到 lookup。

## E — 可执行步骤（Execution）

**1. 先问频率，不要先问效果。**

- 这个界面/操作，用户一天会用几次？
- 拿不到数据就按常识归：快捷键、搜索、列表键盘导航 → 高频；悬停、Tab → 中频；弹窗、提交、删除 → 偶发；引导、成功页 → 罕见。
- **完成标准**：给出一个档位，不是一个模糊的"比较常用"。

**2. 过第一道闸。**
- 高频 → 直接判定不做。**到此结束，不再讨论动效方案**，改给替代（瞬时切换、静态可感知的选中态）。
- 中频 → 只允许极轻方案，且要说明"可以没有"。
- 偶发 / 罕见 → 进入第三道。

**3. 过第二道闸：命名目的。**
- 用六种目的之一造一个句子：「这个动效的作用是让用户知道……」
- 说不出来，或说出来的句子主语是"显得/感觉/氛围" → 判定不做。
- **完成标准**：一句话，含具体的信息传递，不含形容词。

**4. 过第三道闸：选对象。**
- 结果还是过程？进入还是常驻？被操作对象还是周围？
- **完成标准**：指出具体元素，不是"整个页面"。

**5. 检查全局预算。**
- 这一屏现在有几个"重点动效"（持续运动、大面积位移、抢视线的）？**超过 2 个就先砍再谈新增。**
- 这一屏有几处常驻运动（呼吸、漂浮、流动）？**超过 1 处就必须删。**
- **完成标准**：给出数字和该砍哪一个。

**6. 输出判定。**
- 三行：**判定**（加 / 不加 / 换成别的形式）、**理由**（频率档 + 目的或目的缺失）、**替代**（若不加，用什么承担同一功能）。
- 判定为不加时，必须给出替代，否则用户会认为你只是在否决。

## B — 边界（Boundary）★

边界分两类，混淆了会导致该拦的事不敢拦。

### 第一类：直接转出

- **已经决定要加，要写规格。** → `interaction-brief`
- **已经有方案，要挑毛病。** → `motion-audit`
- **知道要什么效果，只问参数。** → `motion-param-calibrate`
- **说不出效果名。** → `motion-term-lookup`
- **加载中显示什么形态。** → `loading-state-pick`

### 第二类：必须介入，但结论是「不该用动效解决」

这一类最容易做错：沉默、或者说"这不归我管"都是错的。用户正打算用错的方式解决问题，需要的正是被拦住——**而拦住的前提是你先应答。**

- **"页面看着廉价，加动效能不能救"。** 必须介入，第一句给判定：廉价感来自排版、留白、层级、字重、配色；动效是放大器不是来源。用动效补排版窟窿，正好产出廉价感。**不能顺着归因去推荐更强的特效。**
- **"页面有点闷"。** 介入，但先问闷在哪里——信息密度不够、层级不清、留白缺失，都表现为"闷"，加动效只是让它动起来，不会让它清楚。
- **给高频操作加动画。** 介入并明确否决，说明理由（第 N 次的成本），给替代方案。
- **无障碍相关。** 介入。任何"大幅位移、视差、持续运动"的方案，无论目的多正当，都必须同时提供 `prefers-reduced-motion` 降级。这是合规问题，不是偏好问题。

### 容易混淆的邻近判断

- **"一页只能一两个"是数量上限，不是准入标准。** 原书只给了上限，很多团队照做之后仍然觉得页面廉价——因为一个都不该有的地方放了一个，也算"一两个"。
- **漂亮的动效不等于对的动效。** 本 skill 不评价做得好不好，只判断该不该有。做得好不好归 `motion-audit`。
