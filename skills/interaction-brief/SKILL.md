# interaction-brief — 把「炫一点」写成能验收的动效规格

## R — 原文（Reading）

> 一个让AI 无法误解的效果描述，通常包含五个要素。套用下面的公式，再配合术语，成功率会高很多：
> ▪触发时机——什么时候开始：页面加载后/ 鼠标悬停时/ 点击后/ 滚动到可见位置时。
> ▪作用对象——谁被动：卡片、按钮、导航栏、整张背景图。
>
> — 《Vibe Coding 前端交互效果术语手册》第一章 1.2

> ▪收尾状态——动完什么样：停在原位/ 恢复原状/ 自动消失/ 只播放一次。
>
> — 同上（第五要素）

> 模糊的说法：“让卡片动起来，高级一点。”——AI 只能自由发挥，结果不可控。清晰的说法：“鼠标悬停卡片时，卡片向上移动4 像素、阴影加深放大，过渡0.25 秒，先快后慢（ease-out），鼠标移开恢复原状。”——几乎一次到位。
>
> — 同上（全书唯一一组显式对照）

---

## I — 方法论骨架（Interpretation）

一次动效沟通要穿过两层，缺任何一层都会返工：

**第一层：定名。** AI 的训练语料里，「行业术语 → 实现代码」是高频配对，所以「悬停上浮（Hover Lift）」这个词本身就是一段被压缩的实现。而「高级一点」「炫一点」在参数轴上没有对应物，模型只能从「通常被认为高级」的分布里采样——每次采样不同，你就在掷骰子。

**第二层：解压。** 术语只说「是什么」，不说「到什么程度」。五个槽位必须填满：

| 槽位 | 要填什么 | 最常漏 |
|---|---|---|
| 触发时机 | 加载后 / 悬停 / 点击 / 滚动到可见 / 拖拽松手 | — |
| 作用对象 | 卡片、按钮、导航栏、整张背景图 | — |
| 变化内容 | 透明度、位移、缩放、旋转、颜色、阴影，或组合 | — |
| 时长与缓动 | 具体秒数 + 曲线 | — |
| **收尾状态** | 停在原位 / 恢复原状 / 自动消失 / 只播放一次 | ★ 几乎总被漏 |

**这个方法的真正杀伤力在最后一个槽位。** 人描述动效时天然只覆盖中间一段（"放大""滑进来"），首尾两头被省略——而验收时出问题的恰恰是这两头：鼠标移开不复位、弹层动完不消失、滚上去又重播一遍。填满五格不是"说得更专业"，是把「创作题」变成「填空题」，把五个自由度逐个关掉。

还有第三层，藏得比较深：**通用公式会让描述"看起来完整"，但每一类交互都有自己的隐性必答项**，恰好落在五格的缝里。拖拽不问「松手后怎样」，弹层不问「怎么关」，描述读起来完全通顺，做出来却是另一个东西。所以完整动作是：**定名 → 填五格 → 按类别补必答项**。

## A1 — 书中的应用（Past Application）

### 案例 1：模糊 vs 清晰的对照（第一章 1.2）
- **问题**：用户想说「让卡片动起来，高级一点」。
- **方法论的使用**：把这个感觉拆成五格——悬停时（时机）/ 卡片（对象）/ 上移 4px + 阴影加深放大（变化）/ 0.25 秒 + ease-out（参数）/ 移开恢复原状（收尾）。
- **结论**：同一句话从"不可控"变成"几乎一次到位"，但信息量并没有增加多少——增加的全是原先被省略的参数。
- **结果**：作者用这一组对照确立全书的核心主张。

### 案例 2：附录 B 的三个填好的模板（入场 / 悬停 / 滚动）
- **问题**：手册里查不到完全匹配的词条时怎么办。
- **方法论的使用**：
  - 入场：「给首页的四个功能卡片加逐条入场（Stagger）效果：页面加载后，卡片依次从下方30 像素处淡入上浮，每张比上一张晚0.1 秒，单张时长0.5 秒，先快后慢。」
  - 悬停：「给导航栏的菜单链接加下划线生长效果：鼠标悬停时，文字下方出现一条2 像素高的主题色下划线，从左向右展开，时长0.2 秒，移开后向左收回。」
  - 滚动：「给整个长页面加滚动显现（Scroll Reveal）：每个版块滚动进入视口80% 位置时淡入上浮20 像素，时长0.6 秒，只播放一次。」
- **结论**：三句都严格服从同一个句式骨架，可以当填法参照——注意每句的结尾都落在收尾状态上。
- **结果**：这是全书唯一被完整演示三遍的方法。

### 案例 3：类别专属必答项（第六、九章章首）
- **问题**：弹层和拖拽的描述"看起来完整"但仍然做错。
- **方法论的使用**：弹层补三词「遮罩、出现方向、关闭方式」；拖拽补三问「拖的是什么、能拖到哪、松手后怎样」。
- **结论**：通用公式管主干，类别字段管最容易返工的那一处。
- **结果**：第六章的 Modal 话术把三词全部写进去了——「背后加50% 黑色遮罩，弹窗从95% 大小放大淡入，点遮罩或右上角关闭按钮收起」。

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个 skill？

1. 描述一个还没做出来的动效，但只会说感觉（"让它活起来""有点质感""丝滑一点"）。
2. 已经写了一段提示词给 AI，结果不像，要重写。
3. 接到了别人的动效描述（设计师口述、需求文档、客户邮件），要判断它能不能直接执行。
4. 要做弹层 / 拖拽 / 表单 / 滚动这类"有专属坑"的交互，怕漏掉关键字段。
5. 要给一个整页方案定规格（首屏、列表、卡片组），需要多条描述并保证风格一致。

### 语言信号（出现这些就该激活）

- "我想让这个XX动一下，但是说不好"
- "怎么写提示词才能让 AI 做出来"
- "帮我描述一下这个效果"
- "这个要求能直接给 AI 吗"
- "要那种高级一点的感觉" / "丝滑一点" / "别那么生硬"
- "AI 做出来跟我想的不一样"

### 与相邻 skill 的区分

- **vs `motion-term-lookup`**：lookup 解决「我不知道这东西叫什么」，输出是候选术语清单；本 skill 解决「我知道要什么，帮我写准」，输出是一句可执行的规格。**如果用户连效果名都说不出，先 lookup 再回来。**
- **vs `motion-param-calibrate`**：本 skill 定"五个槽位各自填什么"，calibrate 只负责第四格（时长与缓动）的专业取值。若用户已有一句完整描述、只想调参数，直接转 calibrate。
- **vs `motion-audit`**：本 skill 是**事前成稿**，audit 是**事后体检**。方向相反：一个是"该怎么写"，一个是"写出来的哪里有毛病"。

## E — 可执行步骤（Execution）

### 零、如果对方是新手，先读这一条

**默认假设对方不懂动效。** 五格是内部工作法，不是让用户填的表。

**不要做的事**：把五格表格丢给他、「请提供时长与缓动曲线」、用「参数轴」「自由度」「渲染成本」这类词。「填不出五格」不是他懒，是他不知道「收尾状态」这个槽位存在——而那正是你该替他补的。

**要做的事**（顺序不能反）：

1. **只问一个问题。** 从他的话里提取，提取到就不问。优先级：时机 > 收尾 > 变化方向。真的一句都提取不到，就给他**三个具体选项**让他挑，不要开放提问。
2. **其余四格你替他填，并说明你怎么填的。** 用他的场景推：说「卡片悬停」就是桌面端，那移动端要补点击替代；说「手机上的列表删掉一行」就用 FLIP 补位。
3. **交付分两层**：
   - 第一层（必须）：一句能直接复制粘贴的话术。**这一层不带任何术语解释。**
   - 第二层（可选）：为什么这几个数这么取。用「因为…所以…」的白话，一次不超过三句。

**「选」比「想」容易。** 对方说「想要高级一点」时，给他三条具体路径并列，每条一句话说清差别，让他挑一条——比问「你想要什么效果」有效十倍。

示例（他说：我想让卡片动一下，高级一点）

> 三个方向，挑一个我给你写好：
> 1. **悬停时卡片微微浮起**——最稳，电脑上好看，手机上不生效（手机没有悬停，要另配点击效果）
> 2. **鼠标移上去时有一束光跟着扫过**——更有科技感，但一页只能用一处，多了就吵
> 3. **加载时卡片依次淡入**——适合一屏有多张卡的情况，是「不土」的默认答案
>
> 你要是想「整体看着更贵」，问题可能在排版和留白，不在动效——这个我得先跟你说清楚。

---

1. **先问时机，不要先问风格。**
   - 完成标准：从用户话里提取出一个时间词（加载后 / 悬停 / 点击 / 滚动到可见 / 拖拽 / 切页 / 长按）。提取不到就问一句「它什么时候开始动？」，只问这一句。
   - 判停条件：若用户连「什么时候动」都说不出、只反复说"好看""高级"，说明需求还没成形 → **停止填表，转 `motion-term-lookup`** 拿 2–3 个候选给他挑。

2. **定名（第一层）。**
   - 用时机定位到 20 类之一，再在该类里找最接近的术语（查 `motion-term-lookup/reference/terminology.md`）。
   - 完成标准：得到一个中英文术语名。查不到就跳过命名，直接进第 3 步用模板组装。
   - 注意：命名不是目的，是压缩手段。有名字就等于免费获得一段 AI 已知的实现。

3. **填变化内容，到参数级。**
   - 位移写像素（"向上 4 像素"），缩放写倍数（"1.05 倍"），旋转写角度，透明度写起止值。
   - 颜色：**只允许两种写法**——十六进制色值，或"用我页面的主题色"。禁止"高级感蓝紫色"这类形容词。
   - 完成标准：这一段念出来，另一个人能不问一句就复现。

4. **填时长与缓动。**
   - 完成标准：有一个具体秒数 + 一个曲线名。数值不确定就交给 `motion-param-calibrate`，不要让 AI 自己挑默认值。

5. **填收尾状态（最容易被跳过，必须显式问）。**
   - 四选一：停在原位 / 恢复原状 / 自动消失 / 只播放一次。
   - 完成标准：能用一句话说出「动完之后它是什么状态」。说不出就是没想清楚，先问用户。

6. **按类别补必答项。**
   - 弹层类 → 遮罩（有无、浓度）、出现方向、关闭方式（关闭按钮 / 点遮罩 / Esc / 拖拽）。
   - 拖拽类 → 拖什么（整卡还是手柄）、能拖到哪（边界）、松手后怎样（落位 / 回弹 / 保存顺序）、拖动中其他元素是否让位。
   - 滚动类 → 只播一次、进入视口的触发位置、是否抵扣吸顶导航高度。
   - 悬停类 → 移动端的替代触发（点击 / 静态展示）；视差是否移动端关闭。
   - 表单类 → 校验时机（实时 / 失焦 / 提交）、错误提示位置、提交期间是否禁用。
   - 完成标准：这一类最常返工的那一处，描述里有了明确答案。

7. **输出成一句话，并做交付前自检。**
   - 句式：「给【元素】加【术语】效果：当【时机】时，【元素】【变化】，时长【X 秒】，【曲线】，【收尾状态/其他要求】。」
   - **自检表**（逐项打勾，缺一项就问用户，不要自己编）：
     - [ ] 时机写了吗
     - [ ] 对象具体吗（"卡片"还是"卡片列表里的每一项"）
     - [ ] 变化有数值吗
     - [ ] 有秒数和曲线吗
     - [ ] 收尾状态写了吗
     - [ ] 这一类的必答项补了吗
     - [ ] 有没有残留形容词（"柔和""高级""自然"）
   - 完成标准：整句读下来没有任何一处需要 AI 猜。

> **可选补强**：若用户手上有想要的效果截图或参考站点，让他一起给，并说「参考这张图的效果，做到我的页面上」+ 术语说明。**注意这是单点依据（仅附录B 一处），不是本书主干方法**——参照物承担"像什么"，术语承担"叫什么"，两者互补但不能互相替代：只说"照这个做"会连带复制无关的布局与配色。

## B — 边界（Boundary）★

### 不要在以下情况使用此 skill

- **问题根源不在动效。** 页面"不好看"多半是排版、留白、层级、字重、色彩的问题。本书自己把「高级感」归给动效（第四章章首、第十二章章首），这是**归因错误**——动效是放大器，不是来源。用动效去补排版的窟窿，越补越廉价。遇到"整体不好看"，先说清这不是一条动效提示词能解决的。
- **需求还没成形。** 用户只会说"高级""好看"，说不出时机。这时候填表等于替他做决定，产出必然返工 → 转 `motion-term-lookup`。
- **效果已经做出来了，只是不满意。** 不要重写 brief，转 `motion-audit`（挑毛病）或 `motion-param-calibrate`（只调参数）。
- **需要多元素时序编排。** 书里的 stagger 只给了"每项晚 0.08 秒"这一种相位关系。真正的节奏编排（谁先谁后、重叠多少、如何随滚动推进）超出本书范围，不要假装能从这个公式推出来。

### 作者在书中警告的失败模式

- **用形容词下单** → AI 每次给出不同结果，改到第五版已经偏离初衷（x01）。
- **用嘴形容颜色** → 页面里出现三种互不相干的紫，与品牌色全面冲突（x07）。
- **拖拽不说三问** → AI 按训练分布补全，行为错了却看起来像对的，比明显坏掉更难发现（x10）。
- **弹层不说三词** → 得到一个进得去出不来的居中白框（p17）。

### 作者的盲点 / 时代局限（蒸馏者补充，非书中观点）

- **`prefers-reduced-motion` 全书零提及。** 一本教人大量加入场、视差、粒子、光斑跟随的手册，完全没提"尊重系统的减弱动态偏好"。这是硬缺陷：视差与大幅位移会让前庭敏感人群眩晕，属 WCAG 层面问题。**本 skill 补充一条固定要求：描述里加一句「尊重系统的减弱动态偏好（prefers-reduced-motion）」**——标注为书外补充。
- **AI 可能超出指令范围添加效果**（你说位移，它给你加个弹跳）。书中无此讨论（见 `rejected/r09`）。**补充：在描述末尾加负向约束**——「不要额外添加其他动画」「只改这一个元素」。
- **本书假设"一次描述就能定稿"**。真实的动效调优是迭代的，且改坏了要回滚而不是叠加修补。本 skill 只负责把第一版写对，不负责收敛过程。

### 容易混淆的邻近方法论

- `motion-term-lookup`：查词，不是写稿。
- `motion-param-calibrate`：只管参数那一格。
- `motion-audit`：审现有方案。
- 设计系统 / 设计令牌：颜色、间距、字体的规范化——那是另一套体系，本 skill 只用它的产出（"主题色"）。
