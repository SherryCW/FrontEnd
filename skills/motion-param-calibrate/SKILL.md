# motion-param-calibrate — 参数不是数字，是语义

## R — 原文（Reading）

> 时长duration
> 动画从开始到结束花多久。
> 常用0.2–0.6 秒；入场动画0.4–0.8 秒；超过1 秒会显得拖沓。
>
> — 《Vibe Coding 前端交互效果术语手册》附录A

> linear
> 匀速，不加速不减速。
> 只用于跑马灯、旋转loading 这类需要匀速的场景。
>
> — 同上

---

## I — 方法论骨架（Interpretation）

大多数人把时长与缓动当成两个独立旋钮，凭手感想拧到哪拧到哪。这本书的处理方式不同：**先定动画在时间轴上扮演什么角色，再由角色决定用哪个参数族，最后才在族内取具体数值。**

顺序反了，就会得到"数值全对但气质不对"的结果——0.3 秒、ease-out、位移 10px，每一项都合规，合起来像一张会动的 PPT。

分派表（角色 → 参数族）：

| 角色 | 曲线 | 时长 | 依据 |
|---|---|---|---|
| 入场 / 出现 | **ease-out**（先快后慢） | 0.4–0.8s | 附录A 明示"首选" |
| 离场 / 消失 | **ease-in**（先慢后快） | 略短于对应入场 | 附录A「适合消失、离场类动画」 |
| 悬停反馈 | ease-out | 0.2–0.3s | 第四章话术 0.25s |
| 点击反馈 | ease-out / spring | 0.15–0.2s | 第五章按压回弹 0.15s |
| 循环 / 往复 | **ease-in-out** | 周期 ≥ 5s，且必须写"缓慢" | 附录A（ease-in-out）+ loop 条款 |
| 匀速永续 | **linear** | — | 白名单：只给跑马灯、旋转 loading |
| 物理手感（松手 / 吸附 / 点赞） | **spring** | — | 附录A「带弹簧回弹感」 |
| 成组出现 | ease-out + stagger | 每项间隔 0.08–0.1s | 第二章逐条入场 |
| 页面转场 | ease-out | 0.4s 左右 | 第十三章 |
| 数值递增（计数） | ease-out，末尾减速 | 可 2s | 第二章数字滚动（例外，见 B） |

**三条底层判断**（书中没明说，是从分派表反推的，此处标注为蒸馏者的综合）：

1. **缓动管节奏，时长管快慢。** 质感主要由后者决定——0.3 秒也能拖沓，也能利落，看的是曲线。想要"更隆重"应该改曲线和位移距离，不是加时长。
2. **入场的物理隐喻是"受阻力停下"，离场是"加速撤走"。** ease-out 让末段减速收稳，符合直觉；ease-in 让末段加速离开，不占注意力。两者用反，入场会显得迟疑，离场会显得依依不舍。
3. **linear 是白名单不是偏好。** 它服务的是"没有起止点"的动作（跑马灯、loading）。一旦用在有明确起止的动画上，就抹掉了"启动加速、停下减速"这两个让运动显得有质量的唯一信号。

还有一条**必加限定**：循环动画不加"缓慢"会很吵（没有终点的运动，注意力无法通过"等它结束"释放）；滚动入场不加"只播放一次"会反复闪烁（元素在视口阈值附近反复穿越）。

## A1 — 书中的应用（Past Application）

### 案例 1：全书 68 条话术里的数值分布
- **问题**：作者需要给每类效果一个"典型"参数。
- **方法论的使用**：按角色取值——淡入 0.6s / 上浮 0.5s（入场）；悬停上浮 0.25s、下划线 0.2s（悬停反馈）；按压回弹 0.15s（点击）；折叠 0.3s、图片放大 0.4s（结构变化）；页面转场 0.4s；渐变流动一个周期 8 秒（循环）；数字滚动 2 秒（计数）。
- **结论**：所有数值都落在角色对应的区间内，只有"计数"和"循环"两类越过了 1 秒线——因为它们不是"移动"，是"持续呈现"。
- **结果**：这张分布表本身就是分派规则的实证，比附录A 的四行文字更有说服力。

### 案例 2：linear 误用的失败标本（附录A + x13）
- **问题**：0.3 秒的上浮，参数"全对"，但看起来像 PPT 的"飞入"。
- **方法论的使用**：检查角色——这是入场（有明确起止），却用了 linear（无起止动作专用）。
- **结论**：错在场景错配，不在曲线本身。曲线没错，派错了族。
- **结果**：改回 ease-out，同样的时长与位移，气质完全不同。

### 案例 3：循环动画的"缓慢"限定（附录A loop + 第十二章粒子）
- **问题**：粒子背景、渐变流动这类永不结束的动画，速度稍快就从背景变干扰源。
- **方法论的使用**：loop 族强制加"缓慢"，周期拉到 5 秒以上（书里渐变流动给的是 8 秒）。
- **结论**："缓慢"不是形容词，是必要参数——不加，AI 会取它见过的中等速度，而那已经太快。
- **结果**：第十二章所有循环类话术都带"缓慢"字样。

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个 skill？

1. 动效做出来了，"说不上哪儿不对"，就是不像专业站点。
2. 不确定该用哪条曲线，在 ease / ease-in-out / linear 之间犹豫。
3. 觉得动画太慢或太快，但不知道改哪个量。
4. 循环动画、滚动动画看着"很吵"或"在闪"。
5. 想给一件东西加"高级感"，正打算靠拉长时长来实现。

### 语言信号（出现这些就该激活）

- "ease 用哪个" / "缓动怎么选" / "spring 还是 cubic-bezier"
- "太慢了" / "太快了" / "显得拖沓" / "一闪而过"
- "看着像 PPT" / "有点廉价" / "不自然" / "发飘" / "没有重量"
- "动效一直在动，好烦"
- "滚上去内容又重播了"
- "想做高级一点，是不是该慢一点"

### 与相邻 skill 的区分

- **vs `interaction-brief`**：brief 管五个槽位填什么，本 skill 只管第四格（时长与缓动）。**前置条件：描述已经完整。** 如果连收尾状态都没定，先回 brief。
- **vs `motion-audit`**：audit 问"该不该有、有几个、有没有性能问题"；本 skill 问"已经有了，怎么调准"。audit 发现问题后常转到这里修。
- **vs `motion-term-lookup`**：查词不查参。查到 Hover Lift 之后，0.25 秒这个数是作者的示例，不是为你算的。

## E — 可执行步骤（Execution）

1. **判角色。**
   - 问：这个动画在时间轴上是什么？进入画面 / 离开画面 / 悬停往复 / 点击回应 / 无限循环 / 匀速滚屏 / 物理松手 / 数值变化 / 页面切换。
   - 完成标准：能填进上面分派表的一行。
   - 判停条件：若角色是"结构展开/收起"（手风琴、折叠面板、抽屉）——这是**离场 + 入场的复合动作**，高度变化用 ease-in-out，且展开与收起时长应略有差异（收起略快）。书中未讨论这个复合动作，此为蒸馏者补充。

2. **选族（按角色查表）。**
   - 完成标准：得到一个曲线名。若用户的描述里已经写了曲线，直接跳到第 5 步做核对。

3. **取数值（族内取值）。**
   - 入场 0.4–0.8s；通用交互 0.2–0.6s；悬停 0.2–0.3s；点击 0.15–0.2s；页面转场 0.4s。
   - 完成标准：有一个具体数字，且在该族区间内。
   - **硬边界：超过 1 秒的"移动类"动画一律砍。** 想要更隆重 → 改曲线（ease-out）、加位移距离，不加时长。

4. **加必加限定（最常被漏的一步）。**
   - 循环类 → 前置"缓慢"，周期 ≥ 5s。
   - 滚动入场类 → 后置"只播放一次，不要来回反复"。
   - 成组出现 → 指定 stagger 间隔（0.08–0.1s/项）。
   - 完成标准：这三类里有涉及的，限定词都写进去了。

5. **反查自检（三个问题，全过才算调准）。**
   - [ ] 时长超过 1 秒了吗？（是 → 除非是计数或循环，否则砍）
   - [ ] linear 用在了有明确起止的动画上吗？（是 → 换 ease-out 或 ease-in）
   - [ ] 循环动画写"缓慢"了吗？滚动入场写"只播放一次"了吗？（否 → 补）
   - [ ] 离场用了 ease-out 吗？（是 → 换 ease-in，否则会"依依不舍"）
   - 完成标准：四项全部无问题，或修改后复述一遍给用户。

## B — 边界（Boundary）★

### 不要在以下情况使用此 skill

- **描述还不完整。** 只有"加个动画"三个字，连变化内容和收尾都没定。先补 brief，否则调参是在给一个不存在的东西调音。
- **问题不在参数。** 页面"不好看"多半是排版与层级问题；动效节奏再准也救不了。本 skill 只解决"这个动效本身的气质"。
- **需要多元素时序编排。** 谁先谁后、重叠多少、如何随滚动推进——书里只有 stagger 一种相位关系，覆盖不了编排。别用本 skill 假装能推出编排。
- **需要无障碍降级。** 书中零提及 `prefers-reduced-motion`；本 skill 的所有参数在系统开启"减弱动态"时应当被整体降级为淡入淡出或直接呈现。这是书外补充，但必须做。

### 作者在书中警告的失败模式

- **入场超过 1 秒** → 用户的因果判断在 300–400ms 内就完成了，多出来的时间不再传递信息，被读作"系统慢"（x12）。
- **linear 用于入场** → 抹掉启动加速与停下减速，像被传送而不是被移动（x13）。
- **循环不加"缓慢"** → 页面没有任何静止间隙，读不完一段正文（x11）。
- **滚动入场漏 once** → 上滚时整屏重播，像页面在抖（x05）。
- **离场用 ease-out** → 关闭动作拖泥带水，连续开关时新旧状态"糊在一起"（p08 的 violation 描述）。

### 作者的盲点 / 时代局限（蒸馏者补充，非书中观点）

- **"超过 1 秒会显得拖沓"有例外，书中自己就违反了两次。** 第二章"数字滚动"给了 2 秒、第十二章"渐变流动"一个周期 8 秒。这不是笔误——**计数类和循环类不是"移动"，是"持续呈现"，判据不同**：读一个变化的数字需要时间，看一个呼吸的背景不需要终点。作者没把这个区分写出来，导致附录A 的硬边界在正文里自相矛盾。本 skill 的处理：1 秒线只适用于位移/缩放/旋转/透明度这类"移动"动画。
- **spring 没给边界。** 附录A 只说"适合拖拽松手、磁铁按钮、点赞弹跳"，没说它不该用在普通入场。实际上 spring 用在结构性入场（面板展开、列表加载）会让界面有"橡皮感"，是不专业的常见来源。
- **参数是经验值，不是物理定律。** 0.2–0.6s 的来源是人对因果延迟的容忍窗口（约 100ms / 1s 两个坎），不是美学标准。遇到区间冲突（比如页面极长、滚动速度极快）时，应按感知判断而不是守区间。
- **默认参数没有考虑设备差异。** 同一套时长在低端安卓机上会因为掉帧被感知为更慢。真机验证不可省。

### 容易混淆的邻近方法论

- 动效设计原则（迪士尼十二原则、Material Motion）——那是"为什么这样动好看"的理论，本 skill 是"填什么数"的操作表。
- 性能预算——那是帧率与合成层的账本，属 `motion-audit`。
