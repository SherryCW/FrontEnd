# motion-term-lookup — 从「我想要那种感觉」到「这叫 Hover Lift」

## R — 原文（Reading）

> ▪第一步：想清楚你要的效果发生在什么时机（入场、滚动、悬停、点击……），翻到对应章节。
> ▪第二步：在表格里找到最像的词条，把“给AI 的描述话术”整句复制下来。
> ▪第三步：把话术里的元素名换成你自己的（比如把“卡片”换成“价格表”），按需调整时长、颜色等数字。
>
> — 《Vibe Coding 前端交互效果术语手册》第一章 1.3

> 前端开发经过二十多年的积累，几乎每一种常见交互都有约定俗成的名字：淡入叫Fade In，滚到顶部固定叫Sticky，手风琴菜单叫Accordion。
>
> — 同上，第一章 1.1

---

## I — 方法论骨架（Interpretation）

这本手册最独特的选择不在词条，而在**索引用什么键**。

它不按技术实现分类（transform / transition / JS / 滚动监听），而按**「什么时候动」**切成 20 类：入场、滚动、悬停、点击、弹层、展开收起、导航切换、拖拽、表单、数据进度、特效、转场与主题。扩展的八类补的是原书整块空缺：手势与多点触控、布局与共享元素、物理与弹簧、文本与数字、3D 与透视、滚动驱动进阶、系统偏好与无障碍、触觉与声音。

这个选择背后有一个关于人的判断：**非专业用户能提供的第一个信息只有时机，不可能是效果名或参数。** 人说得出「鼠标放上去的时候」「划到那儿的时候」「点下去」，说不出「我要 ease-out」。所以检索的主键必须建在时机上，效果名和参数只能由系统反过来追问。

于是检索是一个三级收敛：

```
时机（20 类选 1） → 词条（同类里挑最像的） → 局部改写（换元素名、改数字）
```

第三级之后还有一条退路：查不到完全匹配的，就用 `interaction-brief` 的模板从零组装。**「查现成 → 改参数 → 自己拼」是递进的，卡在哪一级就用哪一级的工具。**

检索时第二个筛选维度是**变化内容**——同样发生在"悬停"，是位移（Hover Lift）、缩放（Image Zoom）、颜色变化（Underline Slide）、还是跟随（Custom Cursor / Spotlight）？时机定类，变化定条。

## A1 — 书中的应用（Past Application）

### 案例 1：一句话定位一个词（第一章 1.1）
- **问题**：用户想说"滚到顶部就固定住的那个导航"。
- **方法论的使用**：抓时机词「滚」→ 归到第三章滚动触发类 → 在类目里按变化内容（固定 + 改样式）筛 → Sticky Header。
- **结论**：术语一旦说出，等于免费获得一段 AI 已知实现，不必描述"怎么让 div 跟着滚"。
- **结果**：作者用「淡入叫 Fade In，滚到顶部固定叫 Sticky，手风琴菜单叫 Accordion」三个例子确立这个方法。

### 案例 2：按时机切分本身就是检索路径
- **问题**：68 个词条，不建索引就无法查。
- **方法论的使用**：按 第二章入场 / 第三章滚动 / 第四章悬停 / 第五章点击 / 第六章弹层 / 第七章展开收起 / 第八章导航 / 第九章拖拽 / 第十章表单 / 第十一章数据进度 / 第十二章特效 / 第十三章转场主题 排列。
- **结论**：章节顺序就是用户的念头顺序。
- **结果**：这是全书的结构骨架，也是本 skill reference 表的组织方式。

### 案例 3：查不到时的退路（附录B）
- **问题**：手册覆盖不到某个组合效果。
- **方法论的使用**：用「给【元素】加【效果术语】效果：当【触发时机】时……」的模板自己组装，术语和五要素同时出现。
- **结论**：词典的边界不该是能力的边界。
- **结果**：作者给了入场 / 悬停 / 滚动三个填好的样例。

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个 skill？

1. 看到别家网站有个效果，想要，但说不出名字。
2. 只会用感觉词描述交互（"丝滑""有点呼吸感""科技感""高级感"）。
3. 想确认自己记忆里的名字对不对（"那个叫 Parallax 还是 Scroll Reveal？"）。
4. 想知道某类场景除了一个方案还有哪些可选（"列表加载除了转圈还能用什么"）。
5. 拿到了一个英文术语，想知道它到底是什么、用在哪。

### 语言信号（出现这些就该激活）

- "这个效果叫什么"
- "就是那种…的效果" / "类似那种…"
- "有没有一种效果，可以…"
- "我说不好，反正就是…"
- "XX 网站首页那个会跟着鼠标走的光斑叫什么"
- "除了转圈还能显示什么"

### 与相邻 skill 的区分

- **vs `interaction-brief`**：本 skill 的输出是**候选清单**（3 个以内，带场景差异），不做完整规格。用户选定之后交给 brief 补五格。**判断线：用户是"在找"，还是"在写"。**
- **vs `motion-param-calibrate`**：术语查到之后要调节奏 → 转 calibrate。本 skill 只给"话术原文"，原话术里的时长是作者的示例值，不是为你的场景算出来的。
- **vs `motion-audit`**：用户问"这个页面用了哪些效果"属于 audit 的观察动作，不属于查词。

## E — 可执行步骤（Execution）

1. **抓时机词。**
   - 从用户话里找时间锚：加载 / 滚 / 滑 / 悬停 / 放上去 / 点 / 拖 / 展开 / 切换 / 切页 / 等。
   - 完成标准：落到 20 类之一。抓不到就问一句「它在什么时候动？」——**只问这一句，不要一次抛三个问题**。

2. **在类目里用「变化内容」做第二筛。**
   - 问自己：这个效果改变的是什么？位移 / 缩放 / 旋转 / 透明度 / 颜色 / 跟随点 / 结构展开 / 内容替换。
   - 完成标准：候选收敛到 1–3 条。

3. **给出候选，每条必须带三样东西。**
   - 中英文术语名 + 一句"它长什么样" + 现成话术（原样给，标注是书里的示例值）。
   - 完成标准：用户能从中挑出一个，不需要你解释第二遍。
   - 排序原则：把最符合他描述意图的放第一个，不要按表格顺序排。

4. **主动指出场景不匹配的风险。**
   - 完成标准：至少说一条"这个效果不适合你的场景"的理由（例：视差在移动端要关；悬停类在触屏上无效；粒子背景会抢正文注意力）。
   - 判停条件：若用户要的是第十二章那类装饰性特效（毛玻璃 / 粒子 / 渐变流动 / 波浪 / 聚光灯 / 卡片翻转），**先提醒过 `motion-audit` 的注意力预算检查**——这类效果是全书自己要求"一页最多一两个"的对象。

5. **交接。**
   - 要成稿 → `interaction-brief`（把选定的术语 + 用户场景一起带过去）。
   - 要调节奏 → `motion-param-calibrate`。
   - 查不到 → 明说"本书没有收录这个"，用 `interaction-brief` 的模板组装，或用最接近的两条类比，**不要硬套一个名字**。

## B — 边界（Boundary）★

### 不要在以下情况使用此 skill

- **用户已经说出术语了。** 直接进 `interaction-brief`，不要在 lookup 里绕一圈。
- **问的是「该用哪个」而不是「叫什么」。** "除了转圈，加载时还能显示什么"这类是**选型**问题：加载类转 `loading-state-pick`，其他场景的选型由 `interaction-brief` 在补规格时一并给出。本 skill 给的是词条，不是建议——把词条当建议给，用户会拿到三个都能用但都不合适的东西。
- **要设计一个书里没有的交互。** 这 68 个词条是 2015–2024 年间沉淀的常见模式，覆盖不了新的交互范式（手势组合、空间交互、滚动驱动的连续动画）。查表查不到就承认查不到。
- **要判断"这个效果该不该加"。** 本 skill 只回答"叫什么"，不回答"要不要"。后者是 `motion-audit` 的职责——而且往往是更该问的那个问题。
- **装饰性特效当搜索目标时。** 见 E-4 的警告：第十二章那 6 条是全书自限条款的靶子。

### 作者在书中警告的失败模式

- **只给形容词、不给术语** → AI 在分布里采样，每次结果不同（x01）。
- **用嘴形容颜色** → 三种互不相干的紫（x07）。
- **说"照这个网站做"却不给术语** → 连带复制无关的布局与配色（p04 的边界）。

### 作者的盲点 / 时代局限（蒸馏者补充，非书中观点）

- **这是一份有边界的词表。** 262 条之外的世界很大，而 AI 的代码能力早已超出这张表。术语的价值正在从"让 AI 听懂"迁移到"让人与人（设计 / 开发 / 客户）对齐验收口径"——后者才是它长期有效的那一半。
- **词表没有版本与来源。** 哪些词是行业共识、哪些是这本书自己的叫法（如"吸顶导航"对应 Sticky Header 是共识，"展开更多"对应 Read More 是泛指），书中没有区分。查表时若遇到 AI 不认识的词，不要断定是 AI 的问题。
- **按时机分类的代价**：一个效果可能同时属于两类（如"卡片翻转"是悬停触发 + 3D 特效）。查不到时换相邻类目再找一次。

### 容易混淆的邻近方法论

- 设计模式的组件库（Material / Ant Design）——那按组件分，不按时机分。
- 动效原则体系（如迪士尼十二原则）——那是"为什么这样动好看"，本 skill 是"这东西叫什么"。两者不冲突但不可互相替代。
