# motion-audit — 上线前的动效体检

## R — 原文（Reading）

> 一页别贪多：每页保留一两个重点动效就够了，全是动效的页面会显得廉价且卡顿。
>
> — 《Vibe Coding 前端交互效果术语手册》附录C 第1条

> 告诉AI 用位移、缩放、透明度做动画（transform 和opacity），不要改宽高和位置布局属性，否则动画会卡顿。这句话直接复制进提示词即可。
>
> — 同上，第3条

> 建议一页最多用一两个，多了会喧宾夺主。
>
> — 同上，第十二章章首

---

## I — 方法论骨架（Interpretation）

这本书的七条踩坑看起来是零散的经验清单，其实可以归成四组互相独立的失分通道。审查动效方案时逐组过一遍，比凭"感觉怪"要可靠得多。

**第 1 组 · 注意力预算。** 动效的唯一语义是"标记重点"。当一页有十个元素在动，每处都在喊"看这里"，标记本身归零——读者得到十个同等重要的东西，等于没有层级。**信号通胀**是"廉价感"的第一来源，而且与实现质量无关：做得再精细，数量超了就是廉价。

**第 2 组 · 渲染成本。** 浏览器的渲染管线是 layout → paint → composite 三段。改 width / height / top / left / margin 会触发重排，影响扩散到兄弟与父节点，每帧重跑整条链；改 transform / opacity 可以只在合成线程完成，跳过前两段。**同一段动画换个属性，成本差一个数量级**——这不是写法习惯，是渲染路径的分叉。

**第 3 组 · 输入设备。** 触屏没有 hover 这个中间态：手指接触即 click，抬起即结束。浏览器为兼容旧代码会模拟 :hover，于是形成"点一下没反应，点两下才行"的双击陷阱；由 :hover 显示的内容在触屏上没有退出路径，因为不存在"移开"。**这不是降级问题，是"换一种触发方式"的问题。**

**第 4 组 · 状态完整性。** 动效只负责"变化的那一瞬"，但用户会停在变化之后。滚动入场没有 once，就在阈值附近反复穿越、反复重播；弹层没有关闭路径，用户只能刷新；提交按钮没有禁用，就能重复下单。这一类缺陷的特点是：**桌面端验收完美，一上真机或一进边界就崩。**

四组之外还有一条元规则：**这四组都不能判断"该不该有动效"**。一本书列了 68 个效果，最后要求你只挑一两个用——这个自我限制才是它的核心，也是它最难被执行的部分。

## A1 — 书中的应用（Past Application）

### 案例 1：一页堆满动效（附录C 第1条 / x02）
- **问题**：每个区块淡入、每张卡片悬停上浮、背景还在流动。
- **方法论的使用**：数重点动效数量 → 远超"一两个" → 判定注意力预算超支；同时查属性 → 多个持续动画叠加 → 判定渲染成本超支。
- **结论**：两条独立链路互相放大：越卡越像模板，越像模板越廉价。花了最多功夫，得到最差评价。
- **结果**：作者的处方是"每页保留一两个重点动效"，其余用静态层级（留白、字重、色阶、分隔线）承担区分。

### 案例 2：只写 hover，不给移动端替代（附录C 第2条 / x03）
- **问题**：桌面端验收完美，手机全部失灵。
- **方法论的使用**：逐个 hover 效果问"触屏上它怎么触发、显示的內容怎么关掉"。
- **结论**：:hover 在触屏上的模拟会吃掉第一次点击；由 hover 唤出的浮层没有退出路径。
- **结果**：所有 hover 话术必须补"移动端改为点击触发或直接静态展示"，并落实为媒体查询（仅在支持 hover 的设备启用）。

### 案例 3：用宽高做展开动画（附录C 第3条 / x04）
- **问题**：展开面板时高度从 0 长到 auto，下方内容被逐帧推挤，抖动、闪白、文字重排。
- **方法论的使用**：查动画属性是不是 transform / opacity。
- **结论**：改布局属性触发重排，影响面扩散；改 transform 只走合成层。
- **结果**：把"用 transform 和 opacity，不要改宽高和位置布局属性"整句写进提示词，作为固定开销。

### 案例 4：装饰性特效抢注意力（第十二章章首 / x09）
- **问题**：粒子在背景飘、波浪在页脚流、导航是毛玻璃、标题是渐变字、卡片还会翻转。
- **方法论的使用**：看特效作用在什么区域——大面积背景上的运动，会与人外周视觉的敏感区直接冲突。
- **结论**：失败点不在"特效不好看"，而在它抢到了注意力却没兑现任何信息（没有交互语义）。
- **结果**：一页最多一两个装饰性特效，且放在不承载正文的区域。

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个 skill？

1. 页面做完了，自己看着"廉价"或"乱"，说不出具体问题。
2. 滚动或悬停时掉帧、卡顿，怀疑是动效的锅。
3. 桌面端好好的，手机上点了没反应 / 点两下才行。
4. 上线前想把方案过一遍，怕有硬伤。
5. 要 review 别人（同事、外包、AI 生成）的动效实现。
6. 页面"到处都在动"，要决定砍掉哪些。

### 语言信号（出现这些就该激活）

- "帮我看看这个动效有没有问题"
- "为什么这个页面看起来廉价 / 很 cheap"
- "为什么这么卡" / "掉帧"
- "手机上没反应" / "要点两下"
- "是不是动效太多了"
- "上线前帮我把一遍"
- 贴了一段 CSS / 一段提示词 / 一个站点链接，问"怎么样"

### 与相邻 skill 的区分

- **vs `interaction-brief`**：方向相反。brief 是"该怎么写"，audit 是"写出来的哪里有毛病"。**判断线：方案存不存在。** 不存在 → brief；已存在 → audit。
- **vs `motion-param-calibrate`**：audit 只标记"这里节奏有问题"，不负责算出正确数值。要修参数 → 转 calibrate。
- **vs `loading-state-pick`**：audit 会发现"长等待用了转圈"，但"该换成什么"属于 loading 的职责。audit 给诊断，loading 给处方。

## E — 可执行步骤（Execution）

**0. 先要材料。**
- 需要：动效清单（哪些元素动了）、关键代码或提示词、目标设备。缺材料时明确说"我看不到实现，只能审描述"。
- **前置动作（来自附录C 第7条）**：如果要动手改，先让 AI / 对方列出"会改哪些文件"，把不可逆改动降级为可审阅清单。

**1. 数组一：注意力预算。**
- 数"重点动效"数量（持续运动、大面积背景运动、抢视线的都算重点）。**> 2 即超支。**
- 看装饰性特效（毛玻璃 / 粒子 / 渐变流动 / 波浪 / 聚光灯 / 翻转）是否落在正文区。
- 完成标准：给出一个数字 + 一句"砍哪几个"的建议，而不是笼统说"太多了"。

**2. 组二：渲染成本。**
- 逐个动画查属性：有没有动 width / height / top / left / margin / padding？→ 致命。
- 有没有同时动 filter / box-shadow / backdrop-filter 在大面积元素上？→ 高风险（书未讨论，蒸馏者补充：这三者同样昂贵）。
- 有没有在滚动事件里同步读写布局（强制同步布局）？→ 高危。
- 视差在移动端是否关闭？
- 完成标准：列出每一处违规的属性与元素，并给出替换方案（translate / scale / opacity）。

**3. 组三：输入设备。**
- 每个 hover 效果：移动端的替代触发是什么？（点击 / 静态展示 / 常驻呈现）
- 由 hover 唤出的内容（Tooltip、下拉、浮层）：触屏上的退出路径是什么？
- 结论必须是"换成什么"，不是"注意兼容"。
- 完成标准：hover 效果有 100% 的替代方案，没有一条悬空。

**4. 组四：状态完整性。**
- 滚动入场：有没有"只播放一次"？（没有 → 必闪烁）
- 弹层：有没有遮罩、出现方向、关闭方式（关闭按钮 / 点遮罩 / Esc / 拖拽）？三条缺一条就是"进得去出不来"。
- 异步操作：提交按钮有没有三态（正常 / 加载 / 禁用 / 结果）？（单点依据，见 `rejected/r02`）
- 组合效果：吸顶导航 + 锚点跳转，有没有抵扣导航高度？（单点依据，见 `rejected/r03`）
- 列表：加载中有没有形态、到底了有没有终止态？
- 完成标准：每一条都有明确的有/无，不留"应该没问题吧"。

**5. 组五（书外补充）：无障碍。**
- 有没有尊重 `prefers-reduced-motion`？视差、大幅位移、粒子是否在减弱动态时降级？
- **全书零提及，这是本书的硬缺陷。** 任何审出"有视差/大幅位移/持续背景运动"的方案，这一项必须报。
- **降级判据是 reduce 不是 remove。** 合格的降级必须保留理解所需的过渡（透明度、颜色），只去掉位移、缩放、视差和循环。把全部动画时长压成 0.01ms 的粗暴兜底只用于存量项目补救，新项目要求按元素写精细版。具体代码见 `motion-param-calibrate/reference/easing-duration.md` 第六节。
- **同时查三项容易漏的**：`:hover` 动效有没有包在 `@media (hover: hover) and (pointer: fine)` 里；主题切换时有没有禁用过渡（否则整页拖影）；循环动画离开视口或切到后台时有没有暂停。

**6. 出分级报告。**
- **致命**（必须改）：导致功能失效或无法退出——hover 无替代、弹层无关闭、提交可重复点击、布局属性动画。
- **明显**（应该改）：导致观感降级——重点动效 > 2、滚动入场无 once、循环无"缓慢"、装饰特效压正文。
- **建议**（可以改）：节奏与细节——时长越界、曲线错配、收尾不明确（转 `motion-param-calibrate`）。
- 完成标准：每条都带「问题 / 后果 / 改法」三样，不写"建议优化一下动效"这种空话。

**7. 给修复顺序，并约定回滚。**
- 顺序：致命 → 明显 → 建议。**不要一次全改**，改完一组验一组。
- **改坏了回滚到上一版，不要在坏结果上叠加修补**——在错误实现上迭代，AI 会以坏代码为上下文继续改，偏差被继承并放大（附录C 第7条）。
- 完成标准：用户知道下一步只做哪一件事。

## B — 边界（Boundary）★

边界分两类，混淆这两类会导致该管的事不敢管。

### 第一类：直接转出，不要介入

- **还没有方案。** 从零写规格 → `interaction-brief`。
- **只想知道某个效果叫什么。** → `motion-term-lookup`。
- **只问一个参数是否合适**（"0.25 秒会不会太快"）。→ `motion-param-calibrate`。
- **要选加载形态**（"加载中显示什么"）。→ `loading-state-pick`。

### 第二类：必须介入，但结论是「这个问题不该由动效解决」

这一类是最容易做错的地方：**沉默、或者说"不归我管"，都是错的。** 用户正打算用错的方式解决问题，需要被拦住——而拦住的前提是你先应答。

- **用户问"页面不好看，是不是动效不够高级"。** 必须介入，第一句给判定：这是排版、留白、层级、字重、配色的问题；动效是放大器，不是来源。用动效去补这些窟窿，恰好是"廉价感"的成因之一。**不能顺着用户的归因去推荐更强的装饰特效。**
- **复杂应用态**（列表增删的布局动画 FLIP、并发操作下的动画中断、乐观更新、局部刷新的状态保持）。必须介入。原书 12 类确实不覆盖，但本仓库扩展类已补：增删补位看 `terminology.md` 第十五章（FLIP / 列表插入 / 列表移除 / 布局动画），并发中断与乐观更新仍无对应词条，要明说超出范围。**不要把书里的词条硬套上去。**
- **需要真机验证的判断。** 介入，但必须声明"以下判断基于代码与描述，帧率、触感、眩晕感只能在真机确认"。
- **无障碍**（`prefers-reduced-motion`）。介入——这是书里完全没有的一项，见下。

### 作者在书中警告的失败模式

全部 7 条踩坑已编入第 1–4 组检查项（x01–x08）。补充三条来自正文的：
- **拖拽缺三问** → AI 按训练分布补全，行为错了却看起来像对的（x10）。
- **颜色用形容词** → 页面里出现三种互不相干的紫（x07）。
- **入场超 1 秒 / linear 用于入场** → 归入"建议"级，转 `motion-param-calibrate`（x12 / x13）。

### 作者的盲点 / 时代局限（蒸馏者补充，非书中观点）

- **完全没提无障碍。** `prefers-reduced-motion` 全书零出现。对一个教人大量加入场与视差的手册，这是硬缺陷——前庭敏感人群会因大幅位移眩晕，属 WCAG 层面问题，不是审美偏好。本 skill 把它列为必查项（组五），并标注为书外补充。
- **把"高级感"归因于动效。** 第四章章首说 hover 是"桌面端精致感的主要来源"，第十二章章首说特效"提升高级感"。两处归因互相矛盾，且都与事实不符（来源是排版与层级）。这导致本书的审查清单**只会做减法，不会做加法**——它能告诉你"动效太多"，不能告诉你"这页缺什么"。
- **默认页面是无状态的展示页。** 原书 12 类里没有一类涉及应用态。扩展类补了布局动画、手势、物理中断这些贴近应用态的条目，但乐观更新、四态设计、并发操作仍无对应词条——审真实产品时这类问题仍需另外判断。
- **"卡顿"只归因于属性选择。** 实际上还有一大类来自动画数量与合成层数量、以及 JS 主线程阻塞。书里只有"别贪多"一句笼统带过。

### 容易混淆的邻近方法论

- Lighthouse / Performance 面板 —— 那是量化工具，本 skill 是结构化清单。两者应该一起用：先清单定位，再工具量化。
- 设计评审（design review）—— 那审视觉与信息架构，本 skill 只审"动效这一层的缺陷"。
